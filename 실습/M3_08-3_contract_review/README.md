# 실습 3 · 계약서 검토 RAG 구현

**50분** · 개인 실습

---

## 오늘 만들 것

약관·가이드라인을 RAG로 만들어 두고, 계약서를 올리면 **한 문장씩 읽어 약관과 비교한 뒤 잘못된 문장을 고쳐 주는 웹**을 만듭니다.

실습 1·2가 "질문 → 답변"이었다면, 이번에는 **계약서 문장 하나하나가 질문**이 됩니다.

```
[벡터DB 만들기]                 [계약서 검토]
약관 PDF 업로드                  계약서 PDF 업로드
   ↓                              ↓
Chunk 생성                      계약서 문장 분리
   ↓                              ↓
임베딩                           문장과 유사한 약관 검색
   ↓                              ↓
벡터DB 저장                      오류 시 수정 문장 생성
                                  ↓
                               [원문] + [수정문구] 출력
```

## 이 폴더에 있는 것

| 파일 | 용도 |
|---|---|
| `시설공사계약약관.pdf` | RAG 문서 (기준이 되는 약관) |
| `협력계약일반약관.pdf` | RAG 문서 (기준이 되는 약관) |
| `계약서_오류정정실습.pdf` | 검토할 계약서 (일부러 오류를 넣어 둔 문서) |
| `붙여넣기용_프롬프트.md` | Cursor에 붙여넣을 프롬프트 |

## 진행 순서

### STEP 1 · 개발 환경 준비 (3분)

1. 탐색기로 **이 폴더(`M3_08-3_contract_review`)** 로 이동 → 주소창에 `cmd` → 엔터

```
pip list > requirements.txt
```

2. Cursor에서 **File → Open Folder → `M3_08-3_contract_review`** 를 열고, 사이드바에서 **New Chat** 을 누릅니다.

### STEP 2 · 프롬프트 입력 (12분)

`붙여넣기용_프롬프트.md` 의 **프롬프트 1**을 통째로 복사해 붙여넣습니다.
Cursor가 진행 여부나 추가 패키지를 물어보면 답해 주세요.

> 이 실습의 품질은 두 가지에서 갈립니다.
> **① 약관을 어떤 크기로 조각낼 것인가 ② 계약서 문장을 어떻게 나눌 것인가**
> 프롬프트의 30글자 분할 설정이 왜 실습 1(500글자)과 다른지 생각해 보세요.

### STEP 3 · 웹 테스트 (15분)

```
python app.py
```

1. **rag 파일 업로드** → `시설공사계약약관.pdf`, `협력계약일반약관.pdf`
2. **계약서 업로드** → `계약서_오류정정실습.pdf`
3. **계약서 검토** 클릭

체크하며 보세요.

- [ ] 업로드할 때 **진행률 바**가 보이는가
- [ ] 검토 결과가 **한 문장씩** 차례로 나오는가 (한꺼번에 나오면 안 됨)
- [ ] 오류 문장은 `[원문]` 아래에 **진한 파란색** `[수정문구]` 가 붙는가
- [ ] 이상 없는 문장은 원문만 나오는가
- [ ] 하단 질문창에 일반 질문을 하면 RAG 없이 답하는가

계약서에서 찾아낸 오류 수: ____ 건

### STEP 4 · 결과 검수 (10분)

수정된 문장 3개를 골라 **약관 PDF에서 근거 조항을 직접 찾아** 맞는지 확인합니다.

| 원문 요지 | 수정 내용 | 약관 근거 맞음? |
|---|---|---|
| | | O / X |
| | | O / X |
| | | O / X |

> 출력 예시처럼 "조정할 수 **없다**" → "조정할 수 **있다**" 같은 한 글자 차이를 잡아냈다면 성공입니다.
> 반대로 **멀쩡한 문장을 고쳤다면** 그것도 기록하세요. AI 검토는 사람의 최종 확인이 꼭 필요합니다.

### STEP 5 · 에러 보완 (10분)

에러나 이상 동작은 **STOP · COPY · TELL** 로 Cursor에 전달합니다.
수정이 끝나면 다시 실행해 확인합니다.

## 잘 안 될 때

| 증상 | 이렇게 말하세요 |
|---|---|
| 이미 설치된 패키지를 업데이트·재설치하려 한다 (`-U`, `--upgrade`, 다른 버전 지정) | 승인하지 말고 **거절**한 뒤 `이미 설치된 패키지는 업데이트하지 말고 설치된 버전을 그대로 써줘` |
| 결과가 한꺼번에 나온다 | `검토 결과를 문장 하나 끝날 때마다 화면에 바로 보내줘 (스트리밍)` |
| 문장이 중간에 잘려서 검토된다 | `계약서는 글자 수가 아니라 줄 단위(조항 단위)로 나눠서 검토하게 바꿔줘` |
| 멀쩡한 문장도 다 고친다 | `약관과 명백히 충돌할 때만 수정하고, 애매하면 원문만 출력하게 해줘` |
| 진행률이 안 보인다 | `업로드와 임베딩 진행률을 웹 화면에 바 형태로 표시해줘` |
| 수정문구가 파란색이 아니다 | `[수정문구] 줄은 진한 파란색 글씨로 표시해줘` |

## 완료 기준

- 약관 2개 업로드 → 계약서 업로드 → 검토 결과가 문장 단위로 출력되었다
- 수정 문장 3개를 약관 근거와 대조해 확인했다
