 여기부터 복사
─────────────────────────────────────────────────────────

이 폴더에 agent.py 를 만들어줘. 출장비 정산서를 사내 규정에 따라 검토하는 에이전트야.

[역할]
정산서 폴더의 정산서 8건을 한 건씩 검토해서
승인 / 감액 승인 / 보완 요청 / 사람 확인 필요 중 하나로 판정하고 저장한다.
8건이 끝나면 결과를 검수하고, 검수에 실패한 건은 한 번 더 검토한다.

[이 폴더의 파일]
 - 정산서/*.json          : 정산서 8건 (C01~C08)
 - 한빛소재_복리후생_근무제도_안내.md : 규정집(안내서). 출장은 제18조~제20조
 - 출장비_정산_세부지침.md : 판정 기준·증빙·감액·환율·정산 기한·휴무일·검토 절차(제9조)
 - 임직원_명부.json        : 사번·이름·직급·부서
 - 환율표.json             : 날짜별 USD 환율
 - 휴무일_2026.json        : 토·일 외 휴무일

[전체 흐름 — 이 부분만 파이썬이 정한다]
 1) 정산서 번호 목록(C01~C08)을 순서대로 하나씩 꺼낸다.
 2) 정산서 1건마다 AI와 "새 대화"를 시작해서 그 건만 검토하게 한다.
    AI가 검토결과_저장 을 부르면 그 건은 끝나고 다음 건으로 넘어간다.
    한 건에 15단계 안에 저장하지 못하면, 파이썬이 그 건을
    판정 "사람 확인 필요", 승인금액 "보류", 근거 "지침 제1조 제1항·제2항",
    사유 "에이전트가 자동 검토를 마치지 못함" 으로 저장하고 다음 건으로 넘어간다.
 3) 8건이 끝나면 파이썬이 결과_검수() 를 한 번 실행한다.
    실패한 건이 있으면 그 건만 실패 사유를 알려주며 새 대화로 한 번 더 검토시킨다.
    그래도 실패하면 2)와 같이 "사람 확인 필요" 로 저장한다.
 4) 그래서 프로그램은 항상 8건 모두 판정된 상태로 끝난다. 마지막에 판정별 건수를 보여준다.

[판단은 AI가 한다 — 이 항목이 제일 중요해]
정산서 1건 안에서는 어떤 도구를 어떤 순서로 몇 번 쓸지 AI가 정한다.
매 단계마다 AI에게 지금까지의 대화를 보여주고, 아래 JSON 하나로 다음 행동을 답하게 해.
   {"단계":"계획|도구사용", "도구":"도구이름", "입력":{인자이름:값}, "이유":"왜 지금 이걸 하는지 한 줄"}
파이썬은 그 도구를 실행한 결과를 AI에게 돌려주고 또 물어본다.
건 안에서 도구를 부르는 순서를 코드에 박아넣지 마.
 - AI가 "단계" 칸에 도구 이름을 넣으면 그 도구를 부른 것으로 보고 처리한다.
 - 같은 도구를 같은 입력으로 또 부르면 실행하지 말고 "이미 실행했다, 다음으로 넘어가라" 고 알려준다.
 - JSON 이 아니거나 없는 도구를 부르면 그 사실과 쓸 수 있는 도구 목록을 알려주고 다시 묻는다.
 - 도구 실행 중 오류가 나도 멈추지 말고 오류 내용을 AI에게 돌려준다.

[AI가 쓰는 도구 7개] — 파이썬 함수로 만들고 시스템 프롬프트에 이름·입력·하는 일을 적어줘
 1) 정산서_요약(번호)
    정산서에서 "사실"만 계산해서 돌려준다. 규정의 한도 금액이나 판정은 넣지 않는다.
    신청자, 출장구분, 출장지, 출발일, 복귀일, 제출일,
    출장일수(출발일·복귀일 포함), 숙박일수, 당일출장 여부, 당일출장 왕복이동시간,
    청구항목(항목마다 원화금액 추가. USD는 출발일 환율로 환산, 원 미만 절사),
    영수증_없는_항목(일비 제외), 일비·숙박비·교통비 외 항목, 숙박비 1박 단가,
    청구금액 원화합계, (해외면) 적용환율
 2) 규정_검색(키워드)
    안내서와 세부지침을 "제n조" 제목 단위로 잘라 두고, 키워드(띄어쓰기로 여러 개)가
    많이 나오는 조항 최대 5개를 [{"문서","조항","내용"}] 으로 돌려준다. 조항 제목에 키워드가 있으면 가산점.
 3) 임직원_조회(이름)
    명부에서 같은 이름을 모두 찾아 돌려준다. (0명, 2명 이상일 수 있음)
 4) 정산기한_확인(복귀일, 제출일)
    토·일과 휴무일_2026.json 을 뺀 근무일로 센다. 복귀일 다음 근무일부터 세어 5번째 근무일이 마감일.
    {"마감일","제출일","복귀_다음날부터_제출일까지_근무일수","기한_내_제출"}
 5) 환율_조회(통화, 날짜)
 6) 계산(식목록)
    식 여러 개를 리스트로 받아 한 번에 계산한다. floor(식) 으로 원 미만 절사.
    eval 은 쓰지 말고 ast 로 숫자와 + - * / floor 만 허용한다.
 7) 검토결과_저장(정산서번호, 판정, 청구금액, 승인금액, 근거, 사유, 비고, 보완요청메일)
    정산서번호는 파이썬이 지금 검토 중인 번호로 고정한다.
    금액이 "274,600원" 같은 문자열이면 숫자로 바꾼다. ("보류" 는 그대로)
    검토결과.json 에 저장하고, 검토결과.md (표: 번호|신청자|판정|청구금액|승인금액|근거|사유|비고) 와
    보완요청_메일.md (메일이 있는 건만) 를 다시 만든다.

[파이썬이 쓰는 검수 함수] 결과_검수() — AI에게는 주지 않는다
 저장된 결과를 건별로 검사해서 {"통과": true/false, "실패": {번호: [사유, ...]}} 를 돌려준다.
   ① 저장되었는가  ② 판정이 4가지 중 하나인가  ③ 근거에 "제n조" 가 있는가
   ④ 청구금액이 정산서_요약의 청구금액 원화합계와 같은가
   ⑤ 보완 요청·사람 확인 필요는 승인금액이 "보류" 인가
   ⑥ 승인은 승인금액 = 청구금액, 감액 승인은 0 < 승인금액 < 청구금액 인가
   ⑦ 보완 요청 건에 보완요청메일이 있는가

[AI에게 주는 진행 방법 — 시스템 프롬프트에 넣어줘]
 1. 먼저 정산서_요약으로 사실을 확인하고, 규정_검색("검토 절차")로 지침의 검토 절차를 찾는다.
 2. 검토 절차의 순서대로 필요한 조항을 찾아 하나씩 확인한다. 이미 찾은 조항은 다시 검색하지 않는다.
 3. 금액·날짜·환율은 머릿속으로 계산하지 말고 계산·정산기한_확인·환율_조회 도구를 쓴다.
 4. 청구금액은 정산서_요약의 청구금액 원화합계를 쓴다.
    보완 요청·사람 확인 필요는 승인금액에 "보류" 라고 적고, 보완 요청이면 보완요청메일도 쓴다.
 5. 근거에는 조항을 적는다. 예) 안내서 제18조 제1항, 지침 제3조 제1항
 6. 규정·지침에 없는 비용이나 특정할 수 없는 신청자는 추측하지 말고 "사람 확인 필요" 로 넘긴다.
 7. 판정이 정해지면 검토결과_저장을 부른다. 저장하면 이 정산서 검토는 끝난다.
 ⚠️ 규정의 한도 금액 같은 내용은 코드나 프롬프트에 적지 마. AI가 규정_검색으로 찾게 한다.

[AI 호출]
 - OpenAI Chat Completions API 를 urllib 로 직접 호출한다. (openai 패키지 쓰지 마)
 - 모델은 "gpt-6-luna", "reasoning_effort": "low"
 - "response_format": {"type": "json_object"} 로 JSON만 받는다.
 - temperature, max_tokens 는 넣지 마.
 - API 키는 코드에 적지 말고 os.environ 의 OPENAI_API_KEY 에서 읽는다.
 - 추가 설치 없이 파이썬 표준 라이브러리만 쓴다.

[규칙]
 - 정산서, 규정집, 세부지침, 명부, 환율표, 휴무일 파일은 절대 수정하지 마.
 - 시작할 때 이전 실행의 검토결과.json / 검토결과.md / 보완요청_메일.md 는 지우고 시작한다.

[화면 출력]
두 군데에 같은 내용을 보여준다.
 1) 터미널 — 매 단계 한 줄씩
      [계획] 무엇을 하려는지      [도구] 도구이름(입력)  → 왜: 이유
      [실행] 결과 요약(160자에서 자르기)      [저장] 번호 → 판정 / 승인금액
      [넘김] 사람 확인 필요로 넘긴 건과 이유      [검수] 통과 / 실패 + 사유
 2) run_report.html — 같은 내용을 카드 형태로
      · 매 단계가 끝날 때마다 파일 전체를 다시 쓴다
      · <meta charset="utf-8"> 와 <meta http-equiv="refresh" content="1"> 를 넣는다
      · CSS는 style 태그 안에 직접. 외부 라이브러리·폰트 금지
      · 카드 색 구분: 계획·도구·실행·저장, 검수 실패와 넘김은 빨강, 통과는 초록
      · 맨 위에 "정산서 n/8 · 이 건 k/15 단계 · 저장 m/8건", 맨 아래에 검토결과.md 내용
      · 프로그램 시작할 때 webbrowser.open(pathlib.Path(파일경로).as_uri()) 로 한 번만 연다
        (경로에 한글·공백이 있어도 열리게)
      · ⚠️ HTML 만들기에 실패해도 터미널 출력과 에이전트 동작은 계속되어야 한다
